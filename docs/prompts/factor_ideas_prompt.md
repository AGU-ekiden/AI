# 他のAIに特徴量（ファクター）を考えてもらうためのプロンプト

下の「---」から「---」までをそのまま貼り付けて使う。DB に接続できるAI（読み取り専用の lab_reader を使う）を想定。
返ってきた回答（最後の「提出フォーマット」の部分）を、そのまま特徴量ラボの Claude に貼れば実装に進める。

注意：接続文字列やパスワードはプロンプトに書かない（相手のAIの環境の「秘密の設定」に入れる）。service role の鍵は渡さない。

---

あなたは陸上長距離のデータ分析者です。高校生の競技記録データベースを**読み取り専用で**閲覧し、
「箱根駅伝で活躍する選手」を、高校2年の8月31日までの情報だけで見分けるための**特徴量（ファクター）の案**を考えてください。
特に知りたいのは、**5000mの自己ベストだけでは見落とされる、伸びしろのある選手**を見分ける手がかりです。

## 1. 目的と答え
- 答え（成果）：箱根駅伝で **往路（1〜5区）の区間5位以内、または復路（6〜10区）の区間2位以内** に、高校入学年度+3〜+6年度の4大会のうち1回以上入ったか。学生連合の区間は数えない。
- 基準：**高校2年8月31日までの5000mベスト**だけで予測した場合（世代順の検証での PR-AUC 0.401、偶然の水準 0.159）。
- 評価：候補の特徴量を基準に1つ足して、PR-AUC が上がるか（95%区間つき）と、「毎年10人選んだとき何人当たるか」で判定する。
- 評価に使う世代：**2011年度高校入学以降**（それ以前は収録が薄く、記録なしの意味が違う）。2018年度入学以降は最終確認用に取り置き。

## 2. 絶対に守ること
1. **書き込み禁止**。SELECT だけ。INSERT・UPDATE・DELETE・DROP・CREATE・一時テーブル作成もしない。
2. **締切後の情報を使わない**：特徴量に使えるのは、その選手の**高校2年の8月31日（日本時間）以前**に実施された記録だけ。
   - `athletes.university_raw`（進学先）、`athletes.entry_years`・`run_years`（箱根のエントリー・出走）、大学時代の記録、高2の9月以降の記録は**特徴量に使わない**（答えの漏れになる）。
3. **記録がない＝遅い、ではない**。欠けは欠けとして扱い、0点や最下位で埋める案にしない。
4. 健康・故障・性格などを推測しない。記録の欠落を故障と見なさない。
5. 回答や途中の出力に**選手の氏名・個人ID・個人ごとの値を載せない**。確認用のクエリは**集計（件数・割合・中央値など）だけ**にする。
6. 大量の全件ダンプはしない（必要な集計だけ）。

## 3. データベース（スキーマ rkm、陸マガの選手ページを取り込んだもの）
| 表 | 主な列 | メモ |
|---|---|---|
| athletes | person_id, name, highschool_raw, university_raw, entry_years, run_years, birth_date | 1人1行。**university_raw・entry_years・run_years は特徴量に使用禁止**（漏れ） |
| profiles | profile_id, person_id, identity_role | 陸マガのプロフィール。1人に複数あることがある（重複登録） |
| records | person_id, profile_id, record_id, date, fiscal_year, competition_id, competition_raw, event, event_group, distance_m, round_raw, heat_raw, mark_raw, mark_value（秒）, status, wind, place（着順）, annual_rank_japan, annual_rank_category, affiliation_raw, grade_raw, prefecture_raw, ekiden_leg, ekiden_leg_value, ekiden_leg_rank, in_annual_best | 1レース1行。約21万行 |
| ekiden_legs | person_id, record_id, leg, is_self, leg_rank, leg_value, pass_rank, pass_value | 駅伝のチーム全員の区間成績（本人は is_self=1） |
| splits | person_id, record_id, seq, label_raw, value | 途中計時（ラップ） |
| affiliations | person_id, fiscal_year, affiliation_raw | 所属の履歴 |
| season_bests | person_id, event, fiscal_year, best_value, races | 年度別ベスト（参考） |
| column_docs | table_name, column_name, description | **列の説明書。最初に読むこと** |

データの扱いの決まり（すでに決定済み）：
- 5000m は `event='5000m' AND event_group='track'`。3000mSC は `3000mSC(91.4cm)`。駅伝は `event_group='ekiden'`。
- `records.date` はその種目を実際に走った日。`grade_raw` はレース時点の学年（「2+」は2年）。
- `status` が NM・NI・DNE は記録なし、DNS・DNF・DQ・DSQ は除外。
- 同じ人・同じ日・同じ種目・同じ記録は、別プロフィールや別大会IDでも同じレースとして1つにまとめる（予選と決勝は別）。
- 高校入学年度は「高校所属のレースの年度 −（学年−1）」で出す（食い違いは多数決、8割以上・3件以上）。

## 4. すでに試したもの（すべて「5000mベストに足しても有意には上がらない」）
- 5000m：直近365日／180日ベスト、高1・高2年度ベスト、高1→高2の短縮（秒・率）、直近3・5出走の中央値、記録のばらつき（IQR）、ベスト更新日数
- 他種目：高校3000m・1500mベスト、中学3000m・1500mベスト、中3年度3000mベスト
- 駅伝：全国高校駅伝・都道府県駅伝（高校・中学）・春の高校伊那駅伝・県地区高校駅伝の最高区間順位、全国高校駅伝の出走区間数
- 参考（達成者／未達成者の中央値）：伊那駅伝の区間順位 12位／27位、都道府県駅伝（中学）8位／18位、高校1500m 3:59／4:07、中学3000m 8:57／9:03

## 5. 考えてほしい方向（例。これ以外も歓迎）
- **成長の形**：中学→高1→高2の伸びの速さや加速、記録が頭打ちか伸び続けているか、遅咲きのパターン
- **経験量の少なさ**：出場レース数が少ないのに速い（伸びしろ）、5000mを走り始めた時期
- **レースの中身**：着順（place）や組（heat_raw）、ラップ（splits）の安定性・後半の強さ、風（wind）、記録会と選手権での差
- **相対的な強さ**：同じレース・同じ区間の他の選手との差（ekiden_legs の区間タイム差、区間順位÷出場チーム数）、チームメイトとの比較
- **注目度の代わり**：`annual_rank_japan`（年間ランキング）、全国大会の出場有無 — 「人気」になる前の段階を表すもの
- **環境**：所属校の強さ（同じ高校の他の選手の記録）、都道府県（prefecture_raw）、生まれ月（birth_date があれば早生まれ。学年内の相対年齢）
- **スピードと持久力のバランス**：1500mと5000mの比、3000mと5000mの比

## 6. 進め方
1. column_docs を読み、使えそうな列の**値が入っている割合を入学年度別に**集計して確かめる（2011年度入学以降で十分にあるか）。
2. 案ごとに、達成者と未達成者で値の分布が違うかを**集計だけで**ざっと確かめる。成果ラベルは DB にないので、
   近い代わりとして `records` の箱根（competition_raw に「箱根」を含み「予選」を含まない、event_group='ekiden'）の
   `ekiden_leg`・`ekiden_leg_rank` から「往路5位以内／復路2位以内」を判定してよい（学生連合＝place_raw が OP は除く）。
   ただしこれは**確認用だけ**で、特徴量そのものには使わない。
3. 5000mベストとの相関が高すぎる案（言い換えにすぎないもの）は後回しにする。
4. 有望な順に **5〜15個** にまとめ、下のフォーマットで提出する。

## 7. 提出フォーマット（この形のまま返してください）
```yaml
- id: 英小文字とアンダースコア（例 junior_to_g2_growth_rate）
  name: 日本語の短い名前
  hypothesis: なぜ箱根での活躍（特に5000mベスト以上の伸び）と関係しそうか（1〜3文）
  data: 使う表と列（例 records.mark_value, records.date, records.grade_raw）
  definition: 計算方法をはっきり（対象の種目・期間・集計方法・単位）。締切（高2の8/31）より前だけを使うことを明記
  window: 対象期間（例 中1の4/1〜高2の8/31）
  min_n: 計算に必要な最小件数
  missing: 値が出せない場合の扱い（「記録なし＝遅い」にしない）
  leakage_check: 締切後の情報や進学先・箱根の情報を使っていない理由
  coverage: 2011〜2017年度入学で値が出る人の割合（集計で確認した数字）
  quick_check: 達成者と未達成者の中央値など、集計で確かめた結果（数字。確かめていなければ「未確認」）
  corr_with_5000m_best: 5000mベストとの相関の目安（分かれば）
  sql_sketch: 計算の考え方が分かるSQLの骨組み（集計・個人の値の一覧は出さない形）
  priority: 高 / 中 / 低
```
最後に、全体を通じて気づいたデータの注意点（収録の偏り、表記ゆれ、使えなかった列など）を箇条書きで添えてください。
