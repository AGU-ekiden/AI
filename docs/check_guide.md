# 確認ガイド（日付・学年・重複・箱根）

第2回監査（`python scripts/run_audit.py`）の結果で**データ側の事実**はほぼ分かる。
人が判断するのは「その事実を研究でどう扱うか」と、DBの外（公式結果）との照合だけ。

| 項目 | 監査で分かること（自動） | 人が確認・判断すること |
|---|---|---|
| 日付 | 日付の書式、大会ごとに日付が1つか複数か、同じ大会の予選と決勝で日付が違うか、年度との整合 | 2〜3レースを**大会公式の結果（実施日）**と照合し、`date` が「実際に走った日」か「大会初日」かを決める |
| 学年 | `grade_raw` の書き方の一覧、所属履歴の年度の書き方 | 学年表記（例「高2」「2」）が**そのレース時点の学年**か。入学年度の決め方（学年表記から逆算でよいか） |
| 重複 | 同じ人物の別プロフィールに同じ日・種目・記録がある組の数、プロフィール数の分布 | 重複が多ければ、**統合の基準**（同日・同種目・同記録なら同一とみなすか） |
| 箱根 | 箱根の行数、区間・区間順位の有無、所属名に「連合」を含む行の数 | 学生連合の**相当順位**の出典（公式の参考順位を使うか、タイムから算出するか） |

## 1. 日付：大会初日か、実際に走った日か
- 監査の `multiday_5000_dates` / `interhigh_5000_dates` に、複数日大会の 5000m がラウンド別・日付別に出る。
  - 予選と決勝で**日付が違う** → `date` はラウンドの実施日の可能性が高い。
  - 全ラウンドが**同じ日付**（大会初日）→ 実施日ではない。
- そのうえで、インターハイ等の 5000m 決勝を2〜3件、**大会公式サイトの結果（決勝の日付）**と見比べて確定する。
  例：「2021年 全国高校総体 男子5000m 決勝は○月○日」と監査の日付が一致するか。

## 2. 学年
- 監査の `grade_vocab` に `grade_raw` の書き方が件数つきで出る。
- 判断：その表記が「レース時点の学年」なら、5000m を走った日の年度と学年から高校入学年度を逆算できる。
  人物ごとに複数のレースで逆算結果が食い違う場合は、自動で決めずに保留にする。

## 3. 複数プロフィールの重複
- 監査の `profiles_per_person`（1人あたりのプロフィール数）と `cross_profile_duplicates`（重複候補の組数）を見る。
- 判断：重複候補を「同じ日・同じ種目・同じ記録表記なら同一レース」として統合してよいか。
  必要なら陸マガで2つのプロフィールページを開き、同じレースが両方に載っているか1人分見比べる。

## 4. 箱根の区間順位
- 監査の `hakone_competitions`（箱根の行と区間・区間順位の有無）、`hakone_alliance`（学生連合の行）、
  `ekiden_self`（本人区間フラグ）を見る。
- 判断：学生連合の走者に区間順位が入っていない場合、相当順位をどこから取るか
  （大会公式の記録集の参考順位、またはその年の区間タイムから算出）。
