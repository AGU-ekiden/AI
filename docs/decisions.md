### 1. 8/31 締切で注意すること
- 高2の値は「4/1〜8/31の5か月」、高1は12か月。高1→高2の伸び（09・10）は期間長が違う旨を値に併記する。
- 全国高校総体（例年7月下旬〜8月上旬）は締切前に終わるため、締切をまたぐ保留は起きにくい。
  ただし複数日大会で「その種目を走った日」が未確認の結果は、引き続き保留（初日を実施日と見なさない）。
  実データで保留が多い場合は、種目別の日程の取り込み、または「大会期間全体が窓内なら使える特徴量」の別版定義を検討する。
- 直近365日窓は「前年9/1〜8/31」。

### 3. チーム利用の仕組み
- メンバー追加はサーバー端末で `python3 -m labo.users add --name 氏名 --role editor`。トークンは一度だけ表示され、保存はハッシュのみ。
- 閲覧のみの人は保存・状態変更・計算実行ができない（サーバー側で拒否）。
- **相互確認**：メンバーが作った定義を「計算可能」「研究で採用」にするのは作成者以外のメンバー（`LABO_REQUIRE_SECOND_REVIEWER=false` で解除可）。
- すべての操作は利用者名つきで監査ログに残る。無効化した人は即時ログアウト扱い。

### 4. 推奨構成（接続と保存先）
1. **読み取り**：Supabase に `rkm` を SELECT だけできる専用ロール `lab_reader` を作る（既定で読み取り専用トランザクション・タイムアウト付き）。
2. **研究データの保存**：同じ Supabase の別スキーマ `lab` に、`rkm` への権限を持たない `lab_writer` ロールで保存する。既存データを壊す経路がない構成。
3. **ブラウザからはDBに直接つながない**。接続文字列はアプリのサーバー側の環境変数（`RKM_READONLY_DSN`・`LAB_WRITER_DSN`）だけに置く。service role 鍵は使わない。
4. 実行前後で `rkm` の件数と内容ハッシュを比較して不変を記録。
5. チームが外から使う場合の置き場所（チームのPC＋VPN、または費用のかかるクラウド実行環境）は、費用を確認してから決める。それまではローカル起動。

**利用者にお願いすること**：`docs/supabase_setup.sql` を管理者権限で実行し、2つの接続文字列をアプリを動かす環境の環境変数に設定する（チャットには貼らない）。設定後に段階2（読み取り専用監査）を行う。

### 5. 成果ラベル hakone_leg_top@1
- 達成＝箱根駅伝で **往路（1〜5区）の公式区間順位5位以内** または **復路（6〜10区）の公式区間順位2位以内** を1回以上。往路・復路の達成は別々にも保持（合成点は作らない）。
- 追跡期間（既定・要確認）：高校入学年度Eに対し、E+3〜E+6年度の4大会（例：2018年度入学 → 2022〜2025年1月の大会）。
- ラベルは4種類：達成／追跡完了・未達成（根拠あり）／追跡中／不明。**追跡中・不明は0（未達成）にしない**。
  - 未達成と確定するのは、対象4大会の全区間の公式順位が取り込み済み、かつその人物と箱根結果の照合を人が確認済みの場合だけ。
- オープン参加などの参考記録は達成に数えない（別記）。本人未確認の区間記録があれば「不明」。
- 箱根の結果はこのラベルにだけ使い、特徴量・母集団選定には使わない。

## 2026-10-19（後）日付・学年・重複・箱根

| 項目 | 決定 | 反映（`labo/adapters/rkm_mapping.py` ほか） |
|---|---|---|
| 日付 | `records.date` は**その種目を実際に走った日** | `parse_date`。大会初日として扱う必要はない（複数日大会でも date を実施日として使う） |
| 学年 | `grade_raw` は**レース時点の学年**。「2+」のような表記は2年 | `parse_grade`。高校所属のレースの「年度−(学年−1)」で入学年度を出し、食い違う人は保留（`infer_hs_entry_fy`） |
| 重複 | 複数プロフィールの重複は**1つにまとめる** | `build_duplicate_links`：同一人物・同日・同種目・同記録表記なら同じレース。代表は辞書順で決定的に選ぶ。同じプロフィール内はまとめない |
| 箱根 | 区間順位を扱う際は**学生連合を除く** | 成果定義を **hakone_leg_top@3** に。学生連合の区間は達成に数えず、それしかない人は「不明」。v1・v2 も再現可能 |

- 学生連合の判定は所属名に「連合」を含むか（`is_student_alliance`）。
- 学校段階（高校・大学）の判定は所属名の末尾（「○○高」「○○大」）による暫定ルール。第2回監査の語彙で確認する。
- これにより「学生連合の相当順位の出典」は不要になった。
